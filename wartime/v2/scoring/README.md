# Private evidence scoring

The running Wartime agent is the planner. Scoring is a separate Node process with a96MiB V8 old-space limit (not a total RSS cap),128MiB journal bound,100,000 fact/key cap,10,000 checkpoint cap,256 queued facts and32 in-flight facts. Capture/IPC encoding still has main-loop cost; telemetry measures it. No action waits for points. Initial handshake is bounded; scorer failure is visible/incomplete and does not own or pause gameplay. `score_flush` is an explicit controlled-end operation.

Use [FRESH-WARTIME.txt](../FRESH-WARTIME.txt) and `node wartime/v2/fresh-wartime.mjs ensure` in a fresh private home. Agent name Wartime is independent of the generated game username. New profile enables range-tank and scoring; status never provisions accounts. A fresh ready account has score0 and Attack/Strength XP0. Resume preserves legitimate earned score. Test homes/balances/credentials are never production handoffs.

[rules.json](rules.json) preserves exact amounts. Base skill levels require XP progression; first ready stats/tutorial levels are baseline. XP records compare complete/reset-free nonoverlapping windows >=5min in the same skill/world/XP regime. Level, tool and method differences are context; a changed method starts a complete measurement window but compares against the existing same-skill record. First window establishes baseline without reward. All record changes are observed rates, not isolated causal improvements.

Automatic trusted evidence covers baseLevel/XP, confirmed death/life, verified persisted procedures, and verified mining/bank provenance. Scorer independently reads verified own-scope episodes and journals the immutable proof returned after the durable skill write, so later legitimate skill-description/name updates do not invalidate earned procedure evidence on restart; names/coordinates/expectation-threshold changes cannot farm procedure points. Ore units can earn mining25 and bank25 once, with uncertain/mixed/withdrawal provenance conservative and visible. A coverage gap invalidates uncertain held credits.

Social/clan/PvP/improvement families are implemented as trusted-verifier contracts and tested fixtures. The current SDK collector does not establish all those facts. `score_claim` is always pending, never an award from claimed text; no public tool imports arbitrary verified facts. Friend confirmation requires meeting+gift, then a later PM, then confirmed recruit join. Unavailable proof remains pending. Three-kill streak is conservatively one award for reaching three own kills in a confirmed life; longer streaks earn no extra without clarified eligibility. No trade/message/PK automation is added.

The passive visible-idle classifier is unchanged. It does not prove unnecessary/eligible idle. Penalty eligibility requires fresh ownership, positively confirmed ability, runnable approval, unnecessary inactivity, and absence of lag/travel/animation/cooldown/unresolved helper/genuine agreed stop. A mere pause label is not an exemption. SDK ability proof is currently unavailable; report that uncertainty instead of making unsupported deductions. Improvement points need independent comparable genuine before/after evidence, not counter movement or cloud development achievements. Only monitoring additionally requires gameplay experience not reduced; the other five improvements do not have that extra requirement.

Private append-only ledger records facts, awarded/deducted/corrected records and recovery audit entries, scoped by world/character/run. Input IDs and per-rule semantic keys protect replay/restart; a scorer lease refuses concurrent writers. Rule/engine changes require an explicit audited migration rather than silent old-ledger reinterpretation. Corrections reverse an identified record once and retain the original. Disk/capacity/worker failure exposes incomplete scoring.

Every100 cumulative positive points makes a stable checkpoint eligible. Net score includes deductions; corrections do not repeatedly regenerate thresholds. Batched reports are retrieved via cached status/paged evidence; explicit `score_ack` records presentation durably. No chat message/schedule is created. The agent supplies grounded lessons using actual evidence and records, not a hidden model call.

Tools: `score_status` (cached), `score_ledger:{cursor,limit<=100}`, `score_claim:{rule,refs}` (pending), `score_ack:{threshold}`, `score_flush`. `episode`, `remember`, `skills` and `replay` use actual verified-learning memory. No old provisional/test balance is copied.

The replay benchmark is a passive same-input pipeline off/on comparison of retained recorded intents, not re-execution of the executor or live latency. It uses a separate temporary ledger, held historical snapshots for load, and explicit fixture pacing; no model-thinking claim or live balance is derived from it.
